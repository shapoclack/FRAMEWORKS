# Система учета тем курсовых работ

Веб-приложение на фреймворке **Django** с интерфейсом на **Bootstrap 5**, предназначенное для централизованного учета, распределения и контроля статусов выполнения курсовых работ между студентами и научными руководителями.

Проект разработан в рамках серии практических работ (текущий этап: **Практическая работа №5 — PR5**).

---

## 1. Назначение и предметная область

- **Предметная область:** Учебный процесс в высшем учебном заведении — распределение тем курсовых работ, учет научных руководителей, закрепление работ за студентами и аудит изменения статусов.
- **Целевая аудитория:**
  - *Студенты:* поиск и выбор доступных тем курсовых работ, просмотр информации о руководителях, отслеживание статуса работы;
  - *Преподаватели (научные руководители):* размещение тем, контроль академической нагрузки (лимиты тем), проверка работ, перевод тем по жизненному циклу;
  - *Сотрудники кафедры (методисты):* общий мониторинг процесса распределения тем, статистика по группам, отчетность.

### Сущности предметной области (разработанные в ПР3 и реализованные в Django ORM)
1. **Студент (`Student`)** — ФИО, учебная группа, направление подготовки, e-mail, дата добавления.
2. **Научный руководитель (`Supervisor`)** — ФИО, ученая степень, должность, e-mail, лимит тем (`max_topics` от 1 до 20), дата добавления.
3. **Тема курсовой работы (`Topic`)** — название, описание/аннотация, внешний ключ на руководителя, внешний ключ на студента (nullable), статус (`свободна`, `закреплена`, `на проверке`, `защищена`), дедлайн сдачи, дата создания.
4. **История изменения статусов (`StatusHistory`)** — аудит смены статусов (тема, старый статус, новый статус, дата/время изменения, инициатор изменения).

## 3. Назначение HTTP и элементы HTTP-запроса и HTTP-ответа

В рамках ПР5 изучены ключевые принципы работы протокола **HTTP (HyperText Transfer Protocol)**:

- **Клиент-серверное взаимодействие:** Браузер формирует текстовый **HTTP-запрос**, веб-сервер Django парсит его в объект `HttpRequest`, диспетчер URL направляет запрос в соответствующую `view`-функцию, которая возвращает объект `HttpResponse`.
- **Элементы HTTP-запроса:**
  1. *Стартовая строка (Request Line):* Метод (`GET`, `POST`, `PUT`, `DELETE`), путь к ресурсу (`/coursework/topics/`) и версия протокола (`HTTP/1.1`).
  2. *Заголовки запроса (Headers):* Метаданные клиента (`Host`, `User-Agent`, `Accept`, `Cookie`, `Authorization`).
  3. *Тело запроса (Body):* Передается при отправке данных (POST/PUT), например, поля веб-форм или JSON-полезная нагрузка.
- **Элементы HTTP-ответа:**
  1. *Строка состояния (Status Line):* Версия протокола, цифровой код состояния и поясняющая фраза (`HTTP/1.1 200 OK`, `404 Not Found`).
  2. *Заголовки ответа (Headers):* Метаданные сервера (`Content-Type: text/html; charset=utf-8`, `Content-Length`, `Set-Cookie`).
  3. *Тело ответа (Body):* Сгенерированная HTML-разметка, JSON или статический файл.

> Страница `http://127.0.0.1:8000/http-info/` содержит интерактивный разбор реального текущего HTTP-запроса пользователя (метод, заголовки клиента, query-параметры) и справочник по HTTP-кодам.

## 4. Маршрутизация URL и View-функции

Маршруты проекта разделены по приложениям и подключены через `include`:

| URL-маршрут | View-функция | Назначение |

## 6. Установка и запуск

### Требования
- Python 3.10+ (протестировано на Python 3.13)
- Виртуальное окружение `venv`

### Шаг 1. Активация виртуального окружения и установка зависимостей
```bash
# Windows:
venv\Scripts\activate

# Установка библиотек:
pip install -r requirements.txt
```

### Шаг 2. Применение миграций базы данных
```bash
python manage.py makemigrations
python manage.py migrate
```

### Шаг 3. Наполнение базы демонстрационными данными (из ПР3)
```bash
python manage.py seed_data
```

### Шаг 4. Запуск сервера разработки Django
```bash
python manage.py runserver
```
После запуска перейдите в браузере по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
