Протокол HTTP: Запросы, Ответы и Архитектура

HTTP (HyperText Transfer Protocol) — протокол прикладного уровня передачи данных в сети. В архитектуре Django каждая view-функция принимает объект HttpRequest и обязана вернуть объект HttpResponse.

Структура HTTP-запроса (Request)
  1. Стартовая строка (Request Line):
    Содержит метод, URI ресурса и версию протокола: GET /coursework/topics/ HTTP/1.1
  2. Заголовки (Request Headers):
    Метаданные клиента (Host, User-Agent, Accept, Cookie).
  3. Пустая строка (CRLF):
    Разделитель между заголовками и телом сообщения.
  4. Тело сообщения (Message Body):
    Передаётся при методах POST/PUT/PATCH (данные формы, JSON и т.д.). В GET-запросах обычно отсутствует.
Структура HTTP-ответа (Response)
  1. Строка состояния (Status Line):
    Версия протокола, код состояния и поясняющая фраза: HTTP/1.1 200 OK
  2. Заголовки (Response Headers):
    Метаданные сервера (Content-Type: text/html, Content-Length, Set-Cookie).
  3. Пустая строка (CRLF):
    Разделитель заголовков и содержимого ответа.
  4. Тело ответа (Response Body):
    HTML-разметка страницы, JSON-документ или файл, возвращаемый клиенту.
Классы кодов состояния HTTP (Status Codes)
Диапазон Категория Типичные примеры
1xx Информационные 100 Continue, 101 Switching Protocols
2xx Успешные 200 OK (страница загружена), 201 Created (запись создана)
3xx Перенаправление (Redirect) 301 Moved Permanently, 302 Found (редирект после POST)
4xx Ошибки клиента 400 Bad Request, 403 Forbidden, 404 Not Found
5xx Ошибки сервера 500 Internal Server Error, 502 Bad Gateway
